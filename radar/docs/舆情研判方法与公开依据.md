# WorldFirst Radar｜品牌舆情分析方法说明 V1.0

> 适用：万里汇、空中云汇、派安盈、XTransfer、连连国际、PingPong、珊瑚跨境、寻汇、Skyee。2026-10-25版本。  
> 系统输出是**新闻线索的机器初筛**，不是某机构已被证实发生事故的判断，也不是品牌声誉的最终评价。

## 1. 研究依据（机构公开披露，不等于它们公开了内部算法）

1. [HSBC：Reputational risk（2026年10月更新）](https://www.hsbc.com/who-we-are/esg-and-responsible-business/managing-risk/reputational-risk)：以利益相关者预期及由事件或行为造成的负面认知定义风险；强调发现、评估、管理、升级和治理。
2. [DBS：Annual Report 2025，Reputational Risk（第92页）](https://www.dbs.com/iwov-resources/images/investors/annual-report/dbs-annual-report-2025.pdf)：四步法 Prevent / Detect / Escalate / Respond；将外部利益相关者警报、社交媒体评论监测纳入声誉风险管理。
3. [Deutsche Bank：Annual Report 2025，Reputational Risk Management（第123页）](https://investor-relations.db.com/files/documents/other-presentations-and-events/2025/Annual-Report-2025.pdf?language_id=1)：基于风险重要性的升级机制；重大事项提交专门委员会。
4. [巴塞尔框架：SRP30 §30.29](https://www.bis.org/basel_framework/chapter/SRP/30.htm)：强调客户、监管机构、资本市场等相关方的负面感知对业务关系和资金渠道的影响。
5. [AMEC Integrated Evaluation Framework](https://amecorg.com/amecframework/)：传播的曝光产出、受众响应与业务结果分层；宣传稿和转载不等于真实认可。
6. [ISO 22361:2022（摘要）](https://committee.iso.org/standard/50267.html)：危机管理的决策、沟通、训练和改进。

**范围声明**：上述依据支持流程和风险维度。没有证据表明 HSBC、DBS 或德意志银行公开使用本项目的分数阈值。本项目权重是透明的试行规则，须基于人工标注和真实处置历史重新校准。

## 2. 正面、中性、负面、混合、待研判

- **正面**：标题有明确客户赞誉、服务认可、获奖或可核实经营成果。普通“宣布合作、推出产品、完成注册”归为中性，不因是企业新闻而自动判为正面。
- **中性**：客观事实、行业介绍、无明确支持或损害的文章。
- **负面**：明确针对品牌的资金/账户问题、安全问题、监管不利事件、重大服务异常、客户争议。
- **混合**：同一标题存在正反双重明确表述。
- **待研判**：指控、辟谣、否认、疑似、传闻或标题问句中的负面表述，不应直接当作事实。

每条记录输出 `sentiment.label`、`confidence`、`reasons`、`basis`、`requires_review`。目前系统**只取得标题/摘要**；对可验证的实际争议需要阅读全文和人工复核。关键词模型有语义误差，置信度只是试行等级，不是经过统计校准的概率。

## 3. 危机维度与升级门槛

- **事件潜在影响（最高63分）**：资金账户、数据安全、不利监管/执法 = 63；系统故障 = 44；客户争议 = 27。
- **独立发布方覆盖（最多20分）**：在同一近重复事件中，第二个及以后的不同发布方每家加5分，最高20。这里计算的是可识别的**发布方**，并非用户总触达、真实阅读量或跨平台热度。
- **可定位原始文章（最多15分）**：当前源标记 verified 且为企业/媒体发布，每条5分，上限15。标记仅指能追溯原文，不是证实其全部指控。
- **跨社媒独立传播（最多8分）**：至少两家不同社交平台有直达内容、且各条经人工核实后，第二个平台起每个平台加4分，最高8分。来自 Google News 的间接索引线索不计入此项；没有传播量或阅读量数据时不推算触达人数。
- **负面必要条件**：没有明确负面风险词项时，不管报道量多少，危机分均为0。
- **风险级别**：重大事项多方独立且至少两个可定位原始报道、分数≥75为“严重”；≥55并有原始媒体/企业可定位出处为“较高”；其他可定位原文的负面线索≥30为“关注”。
- **搜索线索特别保护**：仅搜索索引、没有可定位独立核验原文时，统一标记“待核验”，不得自动发布“严重危机已发生”。
- **动态上调**：未来获得经过授权的真实平台互动量、独立站点覆盖率、同比增长等指标后再设计；当前没有这些数据，严禁模拟“全网声量”“传播热度”“用户情绪百分比”。

以上数字是项目初版的**产品权重**，非银行、巴塞尔委员会、AMEC或ISO官方阈值。

## 4. 人工处置建议

机器初筛 → 查看原文 → 核实品牌归属与报道时效 → 辨别独立报道/广告/转载 → 核对是否存在真实服务影响与客户规模 → 运营/合规复核 → 更正或升级 → 定期复盘。

V1不会自动向外发送危机通知或公开不利事实断言。推荐将“待核验”的潜在高影响资金、安全、监管事项加入分析师待办；人工确认后再决定对外行动。

## 5. 数据接口

- `radar/data/articles.json`：每条新增 `sentiment` 与 `crisis`。
- `radar/data/reputation.json`：事件去重分组、风险证据、独立发布方数量、方法说明、统计汇总。
- `radar/data/latest.md`、`feed.xml`：现有出口保持兼容。
- `radar/data/status.json`：采集是否成功，不与情感判断可信度混为一谈。

## 6. 下一版本验收前必须补齐

1. 真实全文、引用上下文与对品牌的立场，中文和英文金融领域人工标注集；准确率、召回率、假阳性率。
2. 多平台授权数据源与确切互动字段；严禁把 Google News 当作社交传播统计。
3. 实体消歧、事件归因与否定句、反讽、引用句、第三方指控的稳健语义模型。
4. 历史基线和告警阈值校准；连续抓取与人工反馈闭环。
5. 用户可查看依据、覆盖范围、纠正错误标注并持续回测模型。
