# FX 内参：商务外汇内参编辑规范（v0.2）

本模块面向商务人士、跨境业务与金融行业从业者。产品形态是**最近七天持续更新的资讯 + 解读流**，每条资讯配一段可读的市场意义、对企业收付汇或经营的参考、下一步应观察的证据。首页不设置课程、考试、金融游戏、行情预测器或以仪表盘为中心的入口。

## 内容结构

- Fx/data/articles.json：约每20分钟执行一次 GitHub Actions 采集（调度可能延迟）的 RSS 元数据。只保留发布于最近 7×24 小时且具有有效原始时间的条目。新闻信息不等于已核实全部事实。
- Fx/data/editorial.json：逐条中文编辑内容，使用 items[article.id] 关联；dek=快读，insight=市场解读，business=商务参考，watch=后续核验事项，status 和 evidence 为可选证据字段。
- Fx/data/ai-brief.json：实际核查过原始证据且引用现有文章 ID 的模型分析；不得自动伪造或回填无依据评论。

页面排版遵循唯一的连续阅读流：时间、分类、标题、新闻事实、已完成的分析与证据范围；没有被核验的解读时仅展示原始新闻与来源，不填补空话。顶部仅保留真实官方参考汇率概览，右侧是可交互的官方历史走势图及信源状态；不再以焦点/最新资讯/市场解读/本周观察四处重复同一篇新闻。

## 解读与可信度

- **官方原文已复核**：编辑实际访问并对照官方原文。例如美国联储官员讲话。此状态只确认原文表述，不替机构做价格预测。
- **标题背景解读**：获得 RSS 标题与来源，但报道全文未被独立核对。可以解释经济背景或条件性影响，不能将未确认的数字、结果或因果关系当成事实。
- **AI 核验补充**：依赖 ai-brief.json 的 reviewed=true、method、最近 26 小时的生成时间与存在于七天数据中的 evidence_ids。网页会再次核验这些条件。
- 机构预测不得写成已发生事实；美元兑人民币上涨一般意味着人民币相对美元走弱；未经证明的技术位不可写成官方保证价。
- 所有由英文标题翻译的中文标题都必须保留原文链接与机构身份。
- 没有可靠解读时保留空缺，不能为页面充实而制造观点。
- 版权：仅聚合 RSS 原始标题、发布时间、来源、链接与本站独立撰写的简短解释，不复制第三方全文。

## 读者需要带走什么

每条内参应直接回答四个实用问题：

1. 发生了什么？
2. 为什么外汇市场关注？
3. 与商务人士的外币成本、收款、报价、贸易及资金安排有哪些条件性的联系？
4. 还需要观察哪些数据，有什么风险或反向解释？

语言必须准确、平实、易读。正文保持专业通讯和内参口吻，避免将普通读者当学生授课；不用过度煽动与夸张的市场预测。

## 自动更新与研究编辑

RSS 工作流持续提供最近七天新信息；独立 ChatGPT 定时研究任务阅读新信息并更新高价值解读。新信息首先被标记为待核验，完成原文核查之后，才允许写入 status=primary_checked 和 evidence。若只完成标题背景研究，保留相应标记，不得混为经过核实的市场结论。

已存在 ChatGPT 研究任务仍与 GitHub Actions 属于不同执行环境，不能把订阅能力说成 Actions 内置模型 API。定时触发不代表已经成功完成全部新闻的事件级 AI 解读。

- Python 测试与 node --check Fx/app.js 通过。
- 首页是资讯与解读流；没有独立的机制教学实验室、课程或问答区。
- 桌面和移动端均可连续阅读、筛选、搜索、逐条访问原文。
- 旧于七天的新闻自动从数据及页面退出，前端绝不以假新闻补位。

## 真实汇率数据与刷新策略（2026-11-14）
- 数据来源 1：欧洲央行（ECB）90 天每日欧元参考汇率 [官方 XML](https://www.ecb.europa.eu/stats/eurofxref/eurofxref-hist-90d.xml)。USD/CNY、USD/JPY、USD/HKD、GBP/USD 使用同一发布日期的欧元对两种货币参考汇率做交叉计算：A/B=(A per EUR)/(B per EUR)。并明确标识“同日交叉推算”，不得冒充可成交价格或即时银行报价。
- 数据来源 2：香港金管局（HKMA）[每日港元汇率开放数据](https://apidocs.hkma.gov.hk/documentation/market-data-and-statistics/monthly-statistical-bulletin/er-ir/er-eeri-daily/)。优先使用更晚的官方 USD/HKD 观察，日期相同时优先 HKMA 收市价；不得将港元联系汇率制度上下限当作某时点现价。
- **USD/CNH（离岸人民币）已接入独立第三方日度参考值**：访客浏览器直接查询 ExchangeRate-API 开放端点（CORS，网页标注其要求的来源链接）；无授权重分发，本站不把第三方数据写入公开 GitHub JSON，也不以在岸 CNY 替代 CNH。此值为第三方日度汇率，非官方 TMA 离岸定盘价或可成交报价，当前不宣称具有历史走势图。
- 每一显示条目应提供 pair、value、date、source、source_url、method、kind、近 5 个官方公布日变动百分比和完整原始点序列。变动由确定性代码计算，不交给 AI 编造；低于 6 条有效观察时变动留空。
- 一次或全部 API 抓取失败时，保留上次有出处的数据及原始发布日期，不以本次轮询时间伪装数据发布时间；观察日期超过八个自然日的数值隐藏并显示过期。
- RSS 新增日本央行与国际清算银行央行讲话官方 RSS。美国劳工统计局 CPI 与就业 RSS 曾试接入，但在 GitHub 采集环境返回 HTTPError，已暂停，待验证可用的官方替代渠道后再恢复。每一源单独记录请求成功与失败；来自英文源的原始英文标题未被可靠译审前不得宣称是完整中文解读。
- 采集频率是 GitHub Actions **约每 20 分钟一次**（cron = 7,27,47），不是精确执行保证；每轮同时检查 RSS、ECB 和 HKMA 并发布数据快照。网站在页面保持活动时每 3 分钟检查是否已有新的静态快照，手动刷新按钮只读取已发布数据，不能立即触发后台新采集。ECB 官方参考汇率通常工作日公布一次，周末及假日无新数据。
- 成本与配额：刷新工作流仅负责取数和提交 JSON。现有 GitHub Pages 发布工作流由数据更新提交触发，避免同一轮重复部署；现有 radar 模块不受修改。

- 香港金管局 API 访问成功不等于数据及时。首轮真实采集返回最近 2026-10-31 的数据，而欧洲央行有 2026-11-13 的同日交叉参考，故该日 USD/HKD 采用日期更新的 ECB 交叉参考；页面应标示金管局来源数据滞后。
- 截至第一轮尝试，BLS CPI、就业 RSS 在 GitHub runner 返回 HTTPError，已从活跃采集名单撤下，防止将永久失败源伪装为可用。保留代码研究空间。
- 国际清算银行公开讲话源可能包含非 FX 相关的宏观讲话，增加主题筛选并限制最多 8 条近期信息，避免压倒资讯主流。

## 信息结构精简验收（2026-11-14）
- **内容优先于模块**：首页删除焦点横幅的重复新闻、独立“最新资讯”“市场解读”“本周重点观察”和无结构化事件数据的伪经济日历；不生成仅用于填充页面的卡片。
- 新闻只出现一次：所有收录事件按原始时间连续排列，有实际编辑解读时直接随同新闻显示，解读未完成就留出明确的真实性边界。
- 官方汇率概览及右侧走势图有独立数据用途，可点击汇率选择观察对象；源数据未通过观察日期和数值校验的空缺直接显示“—”。
- 所有交互按钮必须有效：筛选、搜索、更多、原文、核验说明、汇率选择和手动快照刷新；查看走势使用真实公布日历史记录。
- 保留系统中既有的 RSS 采集、编辑自动任务、数据和舆情雷达模块，视觉改造不触碰其采集与发布逻辑。

## 2026-11-14 数据链路与深色终端版整改
- 原页面只读取 Pages 随代码发布的 JSON，GitHub Actions 使用 GITHUB_TOKEN 写入的数据提交无法重新触发普通的 Pages push 工作流，因此发生“GitHub 采集已更新、网页仍停留旧快照”的故障。
- 现在网页优先读取 GitHub main 分支的原始 JSON；若 GitHub 原始文件因地区网络、CORS 或其他故障不可访问，则回退 Pages 本地 JSON，同时显示“网站静态备份”和距上次成功采集的时长，超过70分钟显示“更新延迟”，禁止暗示实时。
- GitHub collector cron 改为 13/33/53 分钟尝试重新同步定时调度；GitHub 平台仍可能推迟或跳过。采集后比对实际新闻、官方行情与信源健康变化；有实质更新或静态 Pages 超过两小时未发布时，显式 workflow_dispatch Pages 任务。避免依赖 GITHUB_TOKEN 的普通 push 触发链。
- UI 为深色财经工作台：近黑石墨色、少量琥珀强调、青色走势图、涨跌色及无衬线细黑体。唯一资讯流与独立数据面板，不增加空壳栏目。
- 数据源采集时间、官方汇率观测日和页面发布时间分别标明。价格变化率为最近5个官方公布日对比，不能冒充实时涨跌幅。

## R14 横向行情带（2026-11-14）
- 首页行情的“R14”是 **14 个观察货币对**，不是“14个实时信源”或“14组实时可成交报价”。14个位置为：USD/CNH、USD/CNY、USD/HKD、EUR/USD、USD/JPY、GBP/USD、AUD/USD、NZD/USD、USD/CAD、USD/CHF、USD/SGD、EUR/GBP、EUR/JPY、EUR/CHF。
- 其中 **13 个观察位**可由既有的 ECB 官方日度欧元参考汇率与香港金管局来源提供或用同一公布日数据确定性交叉计算；数据必须有实际观察日期、来源、来源网址，最近5公布日的变化百分比也只由历史已发布数字推导，不得称为“日内涨跌”。
- **USD/CNH 是离岸人民币，USD/CNY 是境内人民币**。ECB 官方参考数据只有 CNY，无法据此生成 CNH。现在 CNH 值由浏览器直接从 [ExchangeRate-API Open Access](https://www.exchangerate-api.com/docs/free) 获取，失败时尝试 [fawazahmed0 社区汇率公开 API](https://github.com/fawazahmed0/exchange-api)；两者均按来源日期校验。网页按服务方要求提供“Rates By Exchange Rate API”署名，且不把 Open Access 汇率写入网站 JSON 或向第三方重新提供可编程数据访问。此值来自第三方，不能标称 TMA 官方定盘价、银行牌价或实时可成交价。TMA 基准具有单独的公开再发布许可限制，故没有被直接复制。
- 行情带在桌面端自动**横向滚动**，鼠标悬停、键盘焦点和用户手动拖动/左右按钮操作暂停自动滚动。可点击“暂停滚动”；系统要求减少动画时默认不自动移动，仍可手动查看全部14组。
- 持续移动的是**视觉位置**，并非交易行情发生实时变化。网页每3分钟在活动状态检查仓库已公布快照；ECB仅工作日提供日度参考价。不存在数据时显示缺失状态和官方日期，不生成模拟走势。
- 新闻正文仍是唯一资讯流，行情带的视觉滚动不触发额外新闻分类或重复模块。

## FX INTEL 顶栏品牌资产与 CNH 交互校验（2026-11-14）
- 顶栏采用 `Fx/assets/fx-intel-mark.svg` 原生矢量资产作为真实图标和浏览器 favicon，英文极简字标 FX·INTEL 的小橙红点由 CSS 实现，中文“外汇内参”为副字标；与第三方金融媒体品牌保持区别，不复制商标。
- 汇率 R14 仍保持13组 ECB/HKMA 有出处的官方日度参考数据；第14组 USD/CNH 不再恒定留空。仅当浏览器从独立第三方成功取得有明确币种、日期、正数值的离岸报价时才显示，否则明确显示获取失败；不使用 CNY 值代替、也不把失败状态藏掉。
- Open Access 提供方更新频率为每天一次，前端成功或失败均限频，每个会话最多约每小时检查一次，防止滥用 API。仅保留浏览器内存中的一次报价，绝不作为本站公开数据文件重新发布。数据许可参考 [ExchangeRate-API 公开接口条款](https://www.exchangerate-api.com/docs/free)；备选为社区公开日度参考。
- 第三方当前数据只有最新一期，走势面板会清晰写明“没有可核实的连续历史序列”，不连造出两端点或把另一来源的在岸历史串进来。
- 所有新闻/汇率分区只因真实数据出现而出现：不重启焦点卡片、空的经济日历或重复分类面板。

## R14 标题字重与信息真实性验收（2026-11-14）
- 【主要汇率】标题采用无衬线加粗字重750，行情代码字重750，主汇率值750并采用等宽数字，近5个官方公布日变化字重700；来源与观察日控制在小字号细字重，避免抢占主行情视觉中心。行情卡片依然保持14货币对的连续横向滚动，不增加无数据支撑的新模块。
- **官网数据准确性与时效能力边界**：ECB 官方汇率通常在欧洲工作日约16:00 CET发布，仅供参考，不支持按单笔交易成交使用。13组主要外汇来自官方日度参考与交叉计算，不保证秒级实时。CNH 是独立第三方日度参考，提供方 Open Access 每天更新一次，不代表官方离岸定盘价或成交报价。不能对所有币种承诺实时行情。
- **RSS 的可靠性**：GitHub cron 目标约20分钟，官方明确可能因负载延迟甚至丢弃计划运行；RSS 供应商本身还可能延期或故障。页面区分“最近成功拉取时间”“最近尝试时间”与“最新收录新闻的原始发布时间”，不将任何一项伪装为“事件已获独立核实”。
- **失败时的硬性措施**：每次采集后发布前执行真实仓库 JSON 校验，金融数据对照历史序列的最后公布日/收市日、值、近5公布日变化、源机构与官方域名一致性，RSS 对照 7 个预设信源的域名、文章来源地址、时间及字段。前端再次执行同一保守逻辑，不合格的行情不显示数值，不合格的新闻元数据不进入资讯流；问题计入数据状态并显式提示。
- **AI 内容隔离**：新闻原始标题与 RSS 来源只说明“该来源刊载过一则报道”，无法自动证明报道的事实已独立核对。编辑状态“primary_checked”必须存在可访问的证据链接才可能显示为已标记核对；AI研究文本只写“已关联来源的研究补充（结论仍需复核）”。模型和人工仍可能发生错误，用户应打开原文核查，不能宣称零幻觉或绝对准确。
- **其他限制**：域名与新闻源列入白名单并能识别格式错误，仅是数据结构和来源治理，不能验证上游没有错误、是否漏掉新闻、是否存在新闻事实差异。交易级实时数据需要独立授权专业行情供应商及监测 SLA；未具备前不能作实时保证。
